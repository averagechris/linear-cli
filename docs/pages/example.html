linear-cli example

A focused issue workflow

This sanitized transcript shows a common flow: list assigned issues, inspect one issue with comments and history, leave a note, and move it into progress. Identifiers, people, and titles are representative.

Install / downloadOverviewSource repository

1. List assigned issues

The command names and flags are real: linear issues list is available as linear i list, and global output flags can shape JSON for scripts.

$ linear i list --mine --limit 3 --no-color
  
2. Inspect details before changing state
linear issues get accepts one or more identifiers. --comments and --history add collaboration and activity context.
$ linear i get ENG-142 --comments --history --no-color
  
3. Leave an implementation note
Comments can be created through linear comments create or its short alias linear cm create.
$ linear cm create ENG-142 -b "I am going to keep the Linear GraphQL error payload in the rendered details." --no-color
  
4. Move the issue into progress
linear issues update supports state, assignee, title, priority, labels, due date, estimate, project, JSON input, and dry-run previews where documented.
$ linear i update ENG-142 -s "In Progress" -a me --no-color
  
5. Use raw GraphQL when needed
The typed command surface covers common workflows; linear api query and linear api mutate are available for schema-specific automation.
$ linear api query '{ viewer { id name } }' --output json --compact
  
No real Linear workspace data was queried for this page; the transcript is representative and sanitized.
